Adding items from outside the app

Also available: Deutsch.

Last updated: November 25, 2026

With an API key, another program, such as Home Assistant or a small script, puts items on one of your lists without anyone opening the app. The dishwasher finishes, and “Unload the dishwasher” is on the list for today.

What a key can do

A key belongs to exactly one list. There it can add an item or bring an existing one back, and nothing else. It does not read the list, tick anything off or delete anything. An archived list still takes items.

What a key adds belongs to no person in the list: nobody is notified, nobody can thank anyone for it, and it counts for no one in Insights. The item says where it came from: “Added by ‹key name›” („Hinzugefügt von ‹Name›“). Only Admins and the Owner can delete it.

Getting a key

In the app: open the list → ⋮ → “Manage” → “API keys” („Verwalten“ → „API-Schlüssel“). Admins and the Owner of the list can make one if their account has an e-mail address. An anonymous account is let go after two silent years, and a key’s calls do not keep it alive. A list holds at most ten valid keys.

The key starts with dct_ and is shown exactly once; Decito keeps only a fingerprint of it and cannot show it to you again. Store it like a password.

A key may expire on a day you choose; whoever made it, or anyone ranked above them, can extend it. It stops working as soon as the person who made it leaves the list, is removed, deletes their account or loses the right to make keys. And it can never do more than that person may do at that moment.

Security

Design for the key to leak one day. It can then do no more than add or bring back items on this one list, but even that should not last long.

  • One key per service. Then you revoke only that one, and the others keep working.
  • Revoke at the first suspicion. In the app, on the key’s page; it takes effect at once. Every Admin and the Owner can do it, whoever made the key.
  • Only in the header, never in a URL. Addresses end up in histories and logs.
  • Home Assistant keeps secrets in plain text. Every add-on with file access can read secrets.yaml. Never share it when you show your configuration, and keep your backups encrypted.

Example: Home Assistant

secrets.yaml holds the key including the word Bearer, because !secret always replaces the whole value: 

decito_api_key: "Bearer dct_…"

The command goes into configuration.yaml. It sends day and assign_to_maker only when the automation passes them: 

rest_command:
  decito_add_item:
    url: "https://api.decito.app/v1/items"
    method: post
    headers:
      Authorization: !secret decito_api_key
    content_type: "application/json"
    payload: >-
      {% set p = {"title": title} %}
      {% if day is defined %}{% set p = p | combine({"day": day}) %}{% endif %}
      {% if assign_to_maker is defined %}{% set p = p | combine({"assign_to_maker": assign_to_maker}) %}{% endif %}
      {{ p | to_json }}

And an automation that calls it when the dishwasher is done. Replace the sensor and its state with your own: 

automation:
  - alias: "Dishwasher finished → Decito"
    triggers:
      - trigger: state
        entity_id: binary_sensor.dishwasher_running
        from: "on"
        # Which state means "finished" depends on the device.
        to: "off"
    actions:
      - action: rest_command.decito_add_item
        data:
          title: "Unload the dishwasher"
          day: "today"
          assign_to_maker: true

When Decito refuses a call, Home Assistant shows it under Settings → System → Logs. What each call did is shown on the key’s page in the app; look there once after setting it up.

Example: curl

The key comes from the environment variable DECITO_API_KEY, not from the script itself: 

curl https://api.decito.app/v1/items \
  -H "Authorization: Bearer $DECITO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"title": "Dishwasher tabs", "quantity": "1 pack"}'

The call

There is exactly one:

POST https://api.decito.app/v1/items
Authorization: Bearer dct_…
Content-Type: application/json

{
  "title": "Unload the dishwasher",
  "day": "today",
  "assign_to_maker": true
}

In the JSON body:

  • title — the item’s name, 1 to 500 characters and not only spaces. The only required field.
  • day — the day it is planned for: "today" (today by the clock of the person who owns the list) or a date such as "2026-12-24". Not before today, and inside the item’s own span if it has one. Lists without days refuse it.
  • quantity — how much, such as "1 pack"; 1 to 240 characters and not only spaces, on shopping lists only.
  • url — a link kept with the item; starts with http:// or https://, at most 2048 characters. Decito never fetches it; it opens only when someone taps it.
  • assign_to_maker — true assigns the item to the person who made the key. A key assigns no one else. Lists of films, books and games refuse an assignment.

A field the API does not know is refused, never ignored, so a typo shows up on the first call. Fields added later change nothing for a call that does not send them; anything that would break an existing call comes with a new version in the path.

When the item is already there

The title is matched the way the app’s quick add matches it: case, surrounding spaces and German umlauts do not matter, so “Kaese” finds “Käse”. With several matches, an open item comes first, otherwise the most recently changed one. Without a match, a new item is added.

  • An open match gets only what it lacks: an empty day, amount, link or assignee is filled, a different one is left alone. A machine does not overrule a person.
  • A completed match comes back as a fresh round: its checklist unticked, its old amount gone, a day in the past moved to today.
  • A hidden match stays hidden, whether until a later day or with no end date; the call is refused with item_hidden.

The answer

Every success answers the same, whatever happened:

200 OK

{"ok": true, "key_expires_at": null}

Added, brought back or unchanged: the answer does not say, so a key in the wrong hands cannot ask what is on the list. What each call did is shown on the key’s page in the app, for Admins and the Owner. key_expires_at says when the key expires, or is null if it never does.

A refusal changes nothing and says why in its error field: 

422 Unprocessable Content

{"error": "unknown_field", "field": "titel"}
not_found · 404
No such address; the path is /v1/items.
method_not_allowed · 405
Only POST is allowed; the Allow header says so too.
key_missing · 401
No Authorization: Bearer … header.
key_unknown · 401
No such key, often a copying mistake.
key_revoked · 401
The key was revoked, or the person who made it may no longer do so.
key_expired · 401
The key has expired; it can be extended in the app.
action_not_granted · 403
This key may not do that.
json_expected · 415
The Content-Type: application/json header is missing.
body_too_large · 413
The body is larger than 8 KiB; see Limits.
invalid_body · 422
The body is not a JSON object.
unknown_field · 422
A field the API does not know; field names it.
invalid_title · 422
The title is missing, empty or too long.
invalid_day · 422
Neither "today" nor a date.
invalid_quantity · 422
The amount is empty, too long or not text.
invalid_url · 422
Not an http or https link, or too long.
invalid_assign_to_maker · 422
Neither true nor false.
day_in_past · 422
The day is before today.
day_outside_frame · 422
The day lies outside the span the item has.
field_not_on_this_list · 422
This kind of list does not carry the field, such as an amount outside a shopping list.
item_hidden · 409
The matching item is hidden; see When the item is already there.
too_many_items · 409
The list already holds as many items as it may.
rate_limited · 429
Too many calls; see Limits.
unavailable · 503
Decito cannot be reached right now; try again later.

Limits

Each key may make at most:

  • 5 calls in 10 seconds,
  • 30 a minute,
  • 300 an hour,
  • 1000 a day.

Every call counts, a refused one too. Only a call that is itself answered with 429 and rate_limited does not. The Retry-After header and the retry_after field give the length in seconds of the window the key ran over: wait that long.

A call’s body may be at most 8 KiB. A list’s cap on items applies to a key as to everyone else.

Machine-readable, as OpenAPI 3.1: openapi.yaml.
